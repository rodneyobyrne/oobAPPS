This document identifies where reusable oobAPPS source material currently comes from. It is an inventory aid, not a requirement that the new conversational product preserve the current source-site navigation or grouping.

## 2. oobDISCOVERY — separate professional discovery source family

The clinician/Varetto discovery work is not one of the 13 oobSKILLS tools.

Its reusable value for oobAPPS includes:
- source-versus-interpretation separation;
- provenance and evidence-state rules;
- organizing tension / current-state reasoning;
- trust and decision-path questions;
- business-type knowledge structure;
- cross-response pattern governance;
- private result and authenticated continuity architecture.

The clinical wording and therapy-specific constraints should remain in oobDISCOVERY unless intentionally adapted for a nonclinical module.

## 3. oobCREATIVE private project source system

The private ChatGPT Project contains deeper brand truth, founder thinking, persona evolution, service strategy, claims governance, private concepts, and working decisions.

Only deliberately selected downstream-safe material may be translated into the public oobAPPS repository.

## 4. Other implementation sources

### HubSpot
Customer relationship system of record and future continuity/lead state.

### Twilio / ElevenLabs work
Relevant precedent for context-service architecture, human-to-agent handoff, and keeping the operational system of record outside the conversational agent.

### Grant-agent exploration
Relevant precedent for governed knowledge, verified claims, missing-information handling, portable working artifacts, and automated-to-human escalation. It is not part of the initial three-module MVP unless later selected.

## Working language

When discussing source families internally:
- `the 13 oobSKILLS tools` = the current public oobSKILLS interactive set;
- `oobDISCOVERY` = professional discovery/questionnaire and evidence architecture;
- `personas` = compressed internal pattern knowledge;
- `situations` = current recognizable conditions in conversation;
- `Recognition Context` = the structured bridge between conversation, pattern knowledge, bounded tools, and useful action.
