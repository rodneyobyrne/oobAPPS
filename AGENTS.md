# oobAPPS Repository Instructions

This repository is public. Treat every tracked file, comment, test fixture, example, prompt, schema and asset as publishable.

## Source boundary

The private oobCREATIVE ChatGPT Project is the broad thinking environment. It is not a direct dependency of this repository.

A downstream app should receive selected outcomes of private thinking, not the full path used to reach them.

Never commit:

- private ChatGPT conversation history
- unselected brainstorms or abandoned alternatives
- private founder reflections or collaboration notes
- speculative client commentary
- customer or prospect data
- credentials, tokens, API keys or secrets
- private persona-evolution notes
- unsupported claims or invented proof

If a private-source decision is required, use an explicit handoff or selected public snapshot.

## Brand nonnegotiables

- Go deeper, not louder.
- Creative thinking must improve understanding, decisions, connection or action rather than pursue novelty for its own sake.
- Preserve human dignity, context, consent, agency and judgment.
- Technology should support human responsibility, not hide weak decisions or replace accountability.
- Build client capability rather than unnecessary dependency.
- Make complex work understandable without pretending it is simple.
- Do not use hype, manufactured urgency, emotional exploitation or fear-based persuasion.

## Public voice

The app should feel human, thoughtful, curious, clear, direct, emotionally perceptive, practical, collaborative, calm and specific.

Prefer:

**recognition → understanding → choice → practical action**

Avoid:

**insecurity → pressure → exaggerated promise → vague consultation**

Begin with a recognizable situation or useful distinction. Do not diagnose the user as incapable, behind, resistant or uninformed.

Questions should reveal useful distinctions, not manufacture drama.

## Personas and situations

Persona intelligence may guide internal strategy, but persona names must not be presented to users or exposed as public classification labels.

Public app behavior should work from recognizable situations and confirmed context.

Use this operating distinction:

- **pattern knowledge** — reusable knowledge developed from approved research and repeated evidence
- **situation** — what is happening now
- **context** — what makes the current case specific
- **confirmation** — what the user says actually fits
- **action** — the useful next decision or work product

A pattern should lead to a confirming question, not a hidden psychological conclusion.

## Privacy and pattern learning

Separate customer context from generalized pattern intelligence.

Default behavior:

- do not persist raw conversation merely because the app received it
- collect only the minimum information needed for the requested task
- save relationship context only after a deliberate user action
- make saved context viewable, correctable and deletable
- do not put raw ChatGPT transcripts into HubSpot
- generalized learning should prefer derived, de-identified situation signals over raw source language

Anonymization is risk reduction, not permission to collect everything.

## Evidence and claims

Distinguish:

- brand belief
- capability claim
- experience claim
- observable outcome
- measurable result
- testimonial

Do not:

- convert a desired outcome into a past result
- infer a metric from an anecdote
- invent testimonials, clients, credentials, results or case details
- imply sole causation without evidence

Until a verified proof register exists, prefer restrained capability language.

## Product behavior

The free interaction must provide genuine useful value even if the user never becomes a lead.

Do not create a CRM contact simply because someone used an anonymous tool.

Appropriate escalation points include deliberate actions such as:

- save my result
- keep this context for next time
- send me this workfile
- purchase this product
- ask oobCREATIVE for help

The cost and depth of the response should match demonstrated intent. This is **appropriate fidelity**, not intentional degradation of accuracy.

## Reuse before rebuild

Before recreating an assessment, prompt, result, component or workflow, check `docs/REUSE-REGISTER.md` and the source repository.

Classify the existing asset as:

- REUSE
- EXTRACT
- ADAPT
- REDRAFT
- REFERENCE
- RETIRE
- PRIVATE

Where practical, website and ChatGPT surfaces should consume the same decision engine rather than maintain separate copies.

## Human ownership

Use LLMs for conversational understanding, clarification and explanation.

Use deterministic or bounded decision logic where an existing tested engine provides the actual decision.

Do not replace explainable decision logic with unconstrained model interpretation merely because an LLM is available.

The system must be able to reject or revise its first interpretation after user correction.

## Missing direction

When a missing decision materially changes product behavior, do not silently fill the gap with generic best practice and present it as oobCREATIVE policy.

Record unresolved decisions explicitly in the relevant document or issue.
