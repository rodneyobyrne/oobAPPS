# oobCREATIVE Service Routing

This file provides public-safe destinations for app escalation. It does not create a new service catalog.

## Rule

The app should help the user recognize the situation and receive useful value before asking them to diagnose which service they need.

A situation may route to more than one service family. The service family determines scope and delivery; the situation determines entry language and what must be understood first.

---

## Message, Positioning and Identity

Use when the core problem involves:

- brand or mission messaging;
- positioning;
- audience clarification;
- service/program descriptions;
- website copy;
- calls to action;
- expert positioning;
- core narrative development.

Common situation signals:

- work is difficult to explain;
- customers do not understand the value of expertise;
- repeated rewriting for different audiences;
- important nuance is being lost in simplification.

Do not route here merely because the user asks for copy. First determine whether the underlying problem is message clarity, audience understanding, offer structure or something else.

---

## Website Strategy and Visual Refresh

Use when the core problem involves:

- website architecture;
- audience pathways;
- navigation and decision flow;
- content hierarchy;
- website copy;
- visual direction;
- design/implementation;
- search and AI-discovery foundations.

Common situation signals:

- a website no longer reflects the business;
- users cannot find or understand what they need;
- a previous website project has failed or stalled;
- the service has become more nuanced than the existing site can explain.

Do not assume every message problem requires a rebuild.

---

## Communication Systems and Practical AI

Use when the core problem involves:

- communication workflows;
- customer/information handoffs;
- content intake and approval;
- reusable message/content libraries;
- AI use-case selection;
- human-review standards;
- CRM, email, scheduling or tool configuration;
- knowledge systems;
- team implementation support.

Common situation signals:

- growth is making customer flow harder;
- staff manually bridge systems;
- communication is structurally chaotic;
- too much knowledge lives with one person;
- organization wants a practical, responsible use of AI.

Start with the responsibility or handoff, not the software.

---

## Campaigns, Launches and Storytelling

Use when the core problem involves:

- campaign messaging;
- program/service launch;
- fundraising communication;
- human-centered storytelling;
- video/audio/photography/visual direction;
- email/social rollout;
- distribution planning.

Common situation signals:

- an idea is ready for a bounded test;
- a program needs public understanding;
- a mission needs clearer fundraising communication;
- a launch needs coordinated messaging and creative.

Do not turn people served by an organization into raw marketing material. Preserve dignity, consent and context.

---

## Ongoing Communications Support

Use when the organization already has recurring communication work that needs continuing judgment, coordination or refinement.

Possible work:

- strategy/prioritization;
- content planning/editing;
- website updates;
- campaign support;
- visual/media guidance;
- workflow refinement;
- vendor coordination;
- review before publication.

This should not become undefined unlimited access. Scope and participation must remain clear.

---

# Participation language

The private source system currently contains two related participation-language sets:

- Guided / Co-Created / Full Implementation
- DIY Assist / Co-Create / Custom Services

No global app decision has selected one set as final.

Treat participation labeling as unresolved until a specific product/service handoff selects the wording.

---

# Escalation rule

Only offer human service escalation when it is relevant to the result already delivered.

Preferred behavior:

1. explain what the app can resolve now;
2. complete the useful bounded work;
3. identify what remains ambiguous, consequential or implementation-heavy;
4. offer the relevant oobCREATIVE service family as an option.

Avoid generic "book a call" behavior when a more specific next step is available.
